# 旅行信息分享平台：项目实现说明

> 课程设计：实践项目 4“集成前端、服务端及网络数据库设计开发旅行信息分享应用”
>
> 技术栈：PHP 8.4 + MySQL 8.0 + Bootstrap 5（B/S 三层，服务端渲染）
>
> 项目目录：`D:\database_project`

本文档面向课程设计答辩、报告撰写和后续维护，按“运行环境 → 公共基础设施 → 数据库 → 页面模块 → 图片上传 → 安全 → 测试 → 常见问题”的顺序说明每个文件的作用、关键代码和实现思路。

## 1. 项目概况

### 1.1 项目目标

系统围绕旅行的三个阶段组织功能：

| 阶段 | 功能 |
| --- | --- |
| 旅行前 | 攻略发布、筛选、收藏；创建行程；组建队伍；入队申请与审核 |
| 旅行中 | 路线按版本保存与恢复；队伍公告；成员管理；好友私聊；站内通知 |
| 旅行后 | 照片、视频、PDF 资源上传与浏览；评论回复；点赞；好友互动 |

课程设计重点不是做一个“大而全”的商业产品，而是把 **浏览器前端、PHP 服务端、MySQL 数据库** 三层完整打通，并展示数据库设计中的：

- 实体关系与外键；
- `CHECK`、`UNIQUE`、`ENUM` 等约束；
- 视图、存储过程、触发器；
- 事务与行锁；
- 索引与查询优化；
- 软删除、计数冗余、版本化设计。

### 1.2 技术方案

| 层次 | 选型 | 说明 |

| 前端资源 | 本地 Bootstrap CSS/JS | 不依赖 CDN，断网也能演示 |

## 3. 请求处理总流程

本项目没有使用 Laravel/ThinkPHP 这类框架，也没有单一“前端控制器”。每个页面文件本身就是一个入口，打开方式就是访问对应的 `.php` 文件。

一个典型请求的流程如下：

```text
浏览器 GET/POST /guide.php?id=1
        │
        ▼
public/guide.php
        │  require ../app/bootstrap.php
        ▼
app/bootstrap.php
        │  1. define('APP_ROOT', ...)
        │  2. 加载 config.php
        │  3. 设置时区 Asia/Shanghai
        │  4. session_start()
        │  5. require helpers.php / db.php / auth.php
        ▼
public/guide.php 继续执行
        │  query('id') 取参数
        │  db_one()/db_all() 查 MySQL
        │  current_user() 判断权限
        │  处理 POST（verify_csrf）
        ▼
require app/views/header.php
        │  输出 HTML 头部、导航、flash 消息
        ▼
页面 HTML + PHP 循环输出数据
        │  所有用户数据用 e() 转义
        ▼
require app/views/footer.php
        │  关闭 main、输出页脚、加载 JS
        ▼
浏览器收到完整 HTML
```

这种写法的优点是：

- 每个页面都能单独阅读，适合课程设计逐页讲解；
- 公共逻辑集中在 `app/`，页面只关心“取数据、校验、渲染”；
- 不需要配置路由重写，PHP 内置服务器直接按文件路径访问。

缺点是页面之间会有少量重复的权限判断和查询代码；对课设规模来说，这种重复比引入框架更容易解释。

## 4. 公共基础设施

### 4.1 `app/bootstrap.php`：统一启动

每个页面第一行都要求加载它：

```php
require __DIR__ . '/../app/bootstrap.php';
```

它负责：

1. 定义 `APP_ROOT`，后续用 `APP_ROOT . '/app/views/header.php'` 拼绝对路径；
2. 读取 `app/config.php`，保存到 `$GLOBALS['config']`；
3. 设置 `date_default_timezone_set('Asia/Shanghai')`；
4. 把 Session 保存目录设为项目内 `storage/sessions`（Windows 用户 Temp 目录在部分启动方式下不可写），再设置 Session Cookie 参数（`httponly`、`samesite=Lax`）并 `session_start()`；
5. 依次加载 `helpers.php`、`db.php`、`auth.php`；
6. 当 `config('app.debug')` 为 true 时打开 `display_errors`，方便本机调试。

`tools/php/php.ini` 同时把 `sys_temp_dir`、`upload_tmp_dir` 指向 `storage/tmp`，避免文件上传的临时文件落到无权限的用户 Temp 目录。

这样所有页面共享同一套时区、Session 和函数，不会出现“这个页面能登录、那个页面读不到 Session”的问题。

### 4.2 `app/config.php`：配置中心

主要配置：

```php
return [
    'db' => [
        'host' => '127.0.0.1',
        'port' => 3306,
        'name' => 'travel_share',
        'user' => 'travel_app',
        'pass' => 'CHANGE_ME_APP_PASSWORD',
        'charset' => 'utf8mb4',
    ],
    'site' => [
        'name' => '旅行信息分享',
        'base_url' => '',
        'upload_dir' => dirname(__DIR__) . '/public/uploads',
        'upload_url' => '/uploads',
        'per_page' => 9,
    ],
    'app' => [
        'debug' => true,
    ],
];
```

要点：

- `upload_dir` 使用绝对路径，避免不同页面 `include` 时相对路径错乱；
- `upload_url` 是浏览器可访问的 URL 前缀，数据库里只保存 `/uploads/...` 这种相对 URL；
- `per_page` 统一列表分页大小，攻略/行程/队伍/资源列表都用它；
- `base_url` 为空时，`url()` 生成站内绝对路径（以 `/` 开头），部署到子目录时可改为 `/travel` 之类。

### 4.3 `app/db.php`：PDO 单例与查询封装

#### 4.3.1 连接

```php
function db(): PDO
{
    static $pdo = null;
    if ($pdo instanceof PDO) {
        return $pdo;
    }
    $c = config('db');
    $dsn = sprintf('mysql:host=%s;port=%d;dbname=%s;charset=%s', ...);
    $pdo = new PDO($dsn, $c['user'], $c['pass'], [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES => false,
    ]);
    $pdo->exec("SET time_zone = '+08:00'");
    return $pdo;
}
```

关键点：

- `ERRMODE_EXCEPTION`：SQL 出错直接抛异常，页面用 `try/catch` 捕获；
- `FETCH_ASSOC`：查询结果直接是关联数组，模板里用 `$row['title']`；
- `EMULATE_PREPARES=false`：使用 MySQL 原生预处理，避免模拟预处理带来的类型/注入问题；
- `SET time_zone='+08:00'`：保证 `created_at`、`NOW()` 与北京时间一致。

#### 4.3.2 查询封装

| 函数 | 返回 | 用途 |
| --- | --- | --- |
| `db_all($sql, $params)` | `array` | 查多行，如列表 |
| `db_one($sql, $params)` | `?array` | 查一行，如详情 |
| `db_val($sql, $params)` | `mixed` | 查单个值，如 `COUNT(*)` |
| `db_exec($sql, $params)` | `int` | 执行 INSERT/UPDATE/DELETE，返回受影响行数 |
| `db_last_id()` | `int` | 取上一条 INSERT 的自增 ID |

示例：

```php
$guide = db_one('SELECT * FROM `guide` WHERE `id` = ? LIMIT 1', [$id]);
$total = (int) db_val('SELECT COUNT(*) FROM `guide` WHERE `status` = ?', ['published']);
db_exec('UPDATE `guide` SET `view_count` = `view_count` + 1 WHERE `id` = ?', [$id]);
```

所有页面都通过这组函数访问数据库，不直接拼接 SQL 字符串。

### 4.4 `app/helpers.php`：公共函数

#### 4.4.1 输出与 URL

| 函数 | 说明 |
| --- | --- |
| `e($value)` | `htmlspecialchars((string)$value, ENT_QUOTES, 'UTF-8')`，所有用户数据输出必须经过它 |
| `url($path)` | 站内路径拼接 `base_url`；已是 `http(s)://` 的原样返回 |
| `redirect($path)` | `header('Location: ...')` + `exit`，返回类型 `never` |
| `safe_path($path)` | 登录跳转的 `next` 参数校验：只允许 `/` 开头且不是 `//`，防止开放重定向 |
| `with_query($overrides)` | 保留当前 GET 参数并覆盖分页/筛选参数，生成分页链接 |

`with_query()` 的实现思路：

```php
$params = $_GET;
foreach ($overrides as $key => $value) {
    if ($value === null || $value === '') {
        unset($params[$key]);
    } else {
        $params[$key] = $value;
    }
}
$path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
return http_build_query($params) === '' ? $path : $path . '?' . http_build_query($params);
```

这样在攻略列表翻页时，关键词、目的地、季节、标签、排序都不会丢。

#### 4.4.2 请求参数与 Flash

| 函数 | 说明 |
| --- | --- |
| `is_post()` | `$_SERVER['REQUEST_METHOD'] === 'POST'` |
| `input($key, $default)` | 取 POST 值并 `trim`，不存在时返回默认值 |
| `query($key, $default)` | 取 GET 值并 `trim` |
| `flash($type, $message)` | 把一次性提示写入 `$_SESSION['flash']` |
| `flashes()` | 取出并清空所有 flash，供页头渲染 Bootstrap alert |

#### 4.4.3 CSRF

```php
function csrf_token(): string
{
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf_token'];
}

function csrf_field(): string
{
    return '<input type="hidden" name="_token" value="' . e(csrf_token()) . '">';
}

function verify_csrf(): void
{
    $token = (string) ($_POST['_token'] ?? '');
    if (!hash_equals(csrf_token(), $token)) {
        http_response_code(419);
        exit('表单已过期，请返回上一页刷新后重试。');
    }
}
```

所有 POST 表单都：

1. 在 `<form>` 内 `echo csrf_field()`；
2. 在处理 POST 的第一行调用 `verify_csrf()`。

登录成功后 `login_user()` 会清空 CSRF Token，避免旧表单被重复提交。

### 4.5 `app/auth.php`：登录与权限

#### 4.5.1 当前用户

```php
function current_user(): ?array
{
    static $user = false;
    if ($user !== false) {
        return $user;
    }
    $id = (int) ($_SESSION['user_id'] ?? 0);
    if ($id <= 0) {
        return $user = null;
    }
    $user = db_one(
        'SELECT * FROM `user` WHERE `id` = ? AND `status` = "active" LIMIT 1',
        [$id]
    );
    return $user;
}
```

- 用户被管理员禁用后，`status != active`，下一次请求 `current_user()` 返回 null，相当于强制下线；
- 静态缓存避免页头、页面、权限函数重复查同一个用户。

#### 4.5.2 登录

`login_user($login, $password)`：

1. 按用户名或邮箱查 `user`；
2. `password_verify()` 校验 bcrypt 哈希；
3. 检查 `status === 'active'`；
4. `session_regenerate_id(true)` 防会话固定；
5. 写入 `$_SESSION['user_id']`；
6. 清空 CSRF Token；
7. 返回 `['ok' => true/false, 'message' => ...]`。

`logout_user()` 清空 Session 并销毁 Cookie。

#### 4.5.3 权限函数

| 函数 | 规则 |
| --- | --- |
| `require_login()` | 未登录：flash + 跳 `/login.php?next=当前URL` |
| `is_admin()` | `role === 'admin'` |
| `require_admin()` | 非管理员：403 + 提示 |
| `can_edit_guide($guide)` | 作者本人或管理员 |
| `can_edit_trip($trip)` | 行程所有者或管理员 |
| `can_manage_team($team)` | 队长、行程所有者或管理员 |
| `is_team_member($teamId, $userId)` | `team_member.status='approved'` |
| `can_edit_route($tripId)` | 管理员、行程所有者、队长、已通过队员 |
| `unread_notifications_count()` | 当前用户未读通知数 |
| `unread_messages_count()` | 当前用户未读私聊数 |

页面通常先 `require_login()`，再用 `can_*` 判断“能不能看/能不能改”。例如路线编辑：

```php
if (!can_edit_route($tripId)) {
    http_response_code(403);
    exit('无权编辑该路线。');
}
```

### 4.6 公共布局

#### 4.6.1 `app/views/header.php`

职责：

- 解析 `$me = current_user()`；
- 计算未读通知/私聊数；
- 读取 `$pageTitle`、`$activeNav`（当前导航高亮）；
- 输出 `<html>`、Bootstrap CSS、`style.css`；
- 输出顶部导航：首页、攻略、行程、队伍、资源、好友；
- 输出搜索框（提交到 `/guides.php`）；
- 输出通知/私聊角标、用户下拉菜单；

### 5.3 设计取舍

#### 5.3.1 一行程一队、一行程一路线

`team.trip_id` 和 `route.trip_id` 都加 `UNIQUE`。

原因：

- 课设场景中“一个行程组织一支队伍”更符合业务；
- 路线作为一个整体版本化，而不是多个路线竞争；
- 查询简单，行程详情页可以直接 `LEFT JOIN team` / `LEFT JOIN route`。

如果未来要支持“一个行程多个候选队伍/多条路线”，需要去掉 `UNIQUE` 并调整页面。

#### 5.3.2 路线版本化

保存路线时不是 `UPDATE route_item`，而是：

1. 锁定 `route` 行，读 `current_version`；
2. 新版本号 = 当前版本 + 1；
3. 插入新的 `route_version`；
4. 批量插入该版本的 `route_item`；
5. 更新 `route.current_version` 指向新版本。

旧版本不删，所以可以：

- 查看历史版本；
- 把任意旧版本“恢复”为一个新版本（不是覆盖历史）。

这样既保留了“云备份”的语义，也避免并发编辑互相覆盖。

#### 5.3.3 评论/点赞的多态外键

`comment` 和 `like_record` 都允许“攻略评论”或“资源评论”，但不能同时指向两者：

```sql
CHECK (
    (`guide_id` IS NOT NULL AND `resource_id` IS NULL)
    OR (`guide_id` IS NULL AND `resource_id` IS NOT NULL)
)
```

同时保留两个真实外键，分别指向 `guide` 和 `resource`。

为什么不只用 `target_type + target_id`？

- 纯多态字段无法建外键，数据库层面无法保证目标存在；
- 现在两个可空外键 + `CHECK` 既保留引用完整性，又能让查询使用索引。

#### 5.3.4 计数冗余与触发器

`guide` 和 `resource` 都有：

- `view_count`：页面浏览时 `UPDATE ... + 1`；
- `like_count`、`comment_count`、`collect_count`：由触发器维护。

触发器在 `like_record`、`comment`、`guide_collect` 的 `AFTER INSERT/DELETE` 中更新对应计数。减少计数时用：

```sql
SET `like_count` = IF(`like_count` > 0, `like_count` - 1, 0)
```

避免无符号字段减到负数。

#### 5.3.5 软删除

- 用户：`status = disabled`，不物理删除；
- 攻略：`status = hidden/rejected`；
- 资源：`status = hidden/rejected`。

原因：

- 评论、点赞、通知、行程等大量数据引用用户/攻略/资源；
- 物理删除会触发级联，且可能让历史记录失去作者；
- 课设中“禁用/隐藏”更符合内容平台的实际做法。

#### 5.4.2 `sp_search_guide`

参数：

```sql
sp_search_guide(
    p_keyword VARCHAR(100),
    p_destination VARCHAR(100),
    p_season VARCHAR(20),
    p_tag VARCHAR(50),
    p_sort VARCHAR(20),
    p_limit INT,
    p_offset INT
)
```

逻辑：

- `p_limit` 夹在 1..50，`p_offset >= 0`；
- 只查 `status='published'`；
- 关键词对标题/摘要/目的地做 `LIKE`；

#### 5.4.3 `sp_review_join`

参数：

```sql
sp_review_join(
    p_team_id INT,
    p_user_id INT,       -- 申请人的 user_id，不是 team_member.id
    p_operator_id INT,
    p_action VARCHAR(20),-- approve / reject
    OUT p_code INT,
    OUT p_message VARCHAR(100)
)
```

逻辑：

1. `DECLARE EXIT HANDLER FOR SQLEXCEPTION` 回滚；
2. `START TRANSACTION`；
3. `SELECT ... FROM team WHERE id = ? FOR UPDATE` 锁队伍行；
4. 校验操作者是队长；
5. 校验申请记录是 `pending`；
6. 校验队伍 `recruiting` 且未满；
7. `approve`：
   - `team_member.status = approved`；
   - `team.current_members + 1`；
   - 达到上限时 `team.status = full`；
   - 给申请人写通知；
8. `reject`：
   - `team_member.status = rejected`；
   - 给申请人写通知；
9. `COMMIT`，通过 `OUT` 返回 `code/message`。

页面调用：

```php
db_exec('CALL sp_review_join(?, ?, ?, ?, @code, @msg)', [$teamId, $userId, $me['id'], $action]);
$result = db_one('SELECT @code AS code, @msg AS msg');
```

### 5.6 一次真实踩坑：CHECK 与级联外键冲突

第一次执行 `01_schema.sql` 时，MySQL 8.0.45 报：

```text
ERROR 3823 (HY000): Column 'user_id' cannot be used in a check constraint
'chk_friendship_not_self': needed in a foreign key constraint
'fk_friendship_user' referential action.
```

原因：MySQL 不允许 `CHECK` 中用到的列同时带 `ON DELETE CASCADE/SET NULL` 的引用动作。

解决：

- `friendship` 的两个用户外键改为 `ON DELETE RESTRICT ON UPDATE RESTRICT`；
- `comment` 的 `guide_id/resource_id` 外键、`like_record` 的 `guide_id/resource_id` 外键也改为 `RESTRICT`；
- 应用层采用软删除，不依赖数据库级联。

这个问题的处理也影响了后面的设计：评论/点赞的父记录不做物理删除，避免“删除父行时触发器更新正在删除的父行”的边界情况。

#### 6.4.2 攻略详情 `public/guide.php`

流程：

1. `id` 参数校验；
2. 查攻略 + 作者；
3. 非 `published` 时，只有作者/管理员能看，否则 404；
4. `UPDATE guide SET view_count = view_count + 1`；
5. 查标签、评论（含回复）、当前用户是否点赞/收藏；
6. 处理 POST：
   - `action=like`：`INSERT IGNORE INTO like_record`，已存在则 `DELETE`；
   - `action=collect`：同理操作 `guide_collect`；
   - `action=comment`：插入 `comment`，给攻略作者写通知（自己评论自己不通知）；
7. POST 后 `redirect`，避免刷新重复提交。

点赞/收藏切换的核心：

```php
$exists = db_one('SELECT id FROM like_record WHERE user_id=? AND guide_id=?', [...]);
if ($exists) {
    db_exec('DELETE FROM like_record WHERE id=?', [$exists['id']]);
} else {
    db_exec('INSERT INTO like_record (user_id, guide_id) VALUES (?, ?)', [...]);
}
```

计数由触发器自动更新，页面不手动改 `like_count`。

表单字段：

- 标题（≤100）；
- 目的地（≤100）；
- 封面：文件选择 `cover_file`（JPG/PNG/GIF/WebP，≤5MB）；
- 摘要（≤500）；
- 正文（必填）；
- 天数（1–60）；
- 人均费用（≥0）；
- 季节（spring/summer/autumn/winter/all）；
- 标签多选；
- 状态：普通用户 `draft/pending`，管理员可 `published`。

保存流程：

1. 校验文本字段；
2. 调 `save_image_upload($_FILES['cover_file'], 'covers/guides', $uploadError)`；
3. 开事务：
   - `INSERT` 或 `UPDATE guide`；
   - `DELETE FROM guide_tag WHERE guide_id=?`；
   - 逐条 `INSERT guide_tag`；
4. 提交；
5. 如果换了新封面，删除旧文件；
6. 如果是 `pending`，给所有管理员写通知；
7. 跳详情页。

事务保证“攻略正文”和“标签”要么都成功，要么都回滚。

### 6.7 路线模块

#### 6.7.1 路线详情 `public/route.php`

- 按 `trip_id` 查行程；
- 可见性校验同行程；
- 查 `route` + 当前 `route_version` + `route_item`；
- 按 `day_no` 分组，按 `seq` 排序，输出时间线；

- 有权限时显示“编辑路线/版本历史”。

#### 6.7.2 路线编辑 `public/route_edit.php`

表单是动态行：

```text
day_no[]  seq[]  item_type[]  title[]  address[]
start_time[]  end_time[]  cost[]  remark[]
```

前端 `app.js` 负责“添加一行/删除一行”，并自动给新行设置 `day/seq`。

后端校验：

- 天数 1–60；
- 序号 1–99；
- 类型枚举：spot/food/hotel/traffic/other；
- 时间格式 `HH:MM`；
- 同一行的开始/结束时间都填写且格式合法时，开始时间不能晚于结束时间；
- 费用 ≥0；
- 同一天序号不能重复；
- 标题不能为空。

保存：

```php
$pdo->beginTransaction();

$route = db_one('SELECT * FROM route WHERE trip_id=? FOR UPDATE', [$tripId]);
if ($route === null) {
    db_exec('INSERT INTO route (trip_id, title, current_version, updated_by) VALUES (?, ?, 1, ?)', ...);
    $version = 1;
} else {
    $version = (int) $route['current_version'] + 1;
    db_exec('INSERT INTO route_version (route_id, version_no, editor_id, remark) VALUES (?, ?, ?, ?)', ...);
}
// 批量插入 route_item
db_exec('UPDATE route SET current_version=?, updated_by=? WHERE id=?', ...);

$pdo->commit();
```

新版本插入后，旧版本仍然保留。

#### 6.7.3 路线历史 `public/route_history.php`

- 列出所有 `route_version`，显示版本号、编辑者、备注、条目数、时间；
- `?version=N` 查看指定版本；
- 有权限的用户可以“恢复”：
  1. 锁 `route` 行；
  2. 新版本号 = 当前 + 1；
  3. 插入新 `route_version`，备注“恢复自 vX”；
  4. `INSERT ... SELECT` 复制旧版本 `route_item`；
  5. 更新 `current_version`。

恢复不是删除历史，而是把旧内容复制成一个新版本。

## 7. 图片上传的完整实现

### 7.1 需求

原来的攻略/行程/头像/资源封面都是“填 URL”：

```html
<input name="cover" value="/uploads/demo/xiamen.svg">
```

这对课设演示不够直观。改造目标：

1. 用户直接点“选择文件”；
2. 图片复制到项目 `public/uploads/` 下；
3. 数据库只保存 `/uploads/...` 相对 URL；
4. 替换时删除旧图，避免垃圾文件；
5. 失败时给中文错误，不产生孤儿文件。

### 7.2 公共函数

`app/helpers.php`：

```php
function save_image_upload(array $file, string $folder, ?string &$error = null): ?string
```

处理步骤：

1. `UPLOAD_ERR_NO_FILE`：返回 null，调用方保留旧图；
2. 其他错误码：映射中文提示；
3. 大小 ≤5MB；
4. `is_uploaded_file()` 确认是 HTTP 上传；
5. `finfo(FILEINFO_MIME_TYPE)` 白名单：

```php
$allowed = [
    'image/jpeg' => 'jpg',
    'image/png'  => 'png',
    'image/gif'  => 'gif',
    'image/webp' => 'webp',
];
```

6. `getimagesize()` 再验证内容是真图片；
7. 目录 `public/uploads/<folder>/YYYY/mm/`，`mkdir(0775, true)`；
8. 文件名 `date('YmdHis') . '_' . bin2hex(random_bytes(6)) . '.' . $ext`；
9. `move_uploaded_file()`；
10. 返回 `/uploads/<folder>/YYYY/mm/<name>`。

拒绝 SVG 的原因：SVG 可以包含脚本，直接当图片提供有 XSS 风险。

`delete_upload()` 只删除：

- `/uploads/covers/`
- `/uploads/avatars/`
- `/uploads/resources/`

并用 `realpath` 确认目标在 `upload_dir` 内，不误删 `demo/` 或外部 URL。

### 7.3 页面接入

#### 攻略封面

`public/guide_edit.php`：

```html
<form method="post" enctype="multipart/form-data">
  ...
  <input type="file" name="cover_file" accept="image/jpeg,image/png,image/gif,image/webp">
</form>
```

```php
$newCover = null;
$uploadError = null;
$uploaded = save_image_upload($_FILES['cover_file'] ?? [], 'covers/guides', $uploadError);
if ($uploadError !== null) {
    $errors[] = $uploadError;
} elseif ($uploaded !== null) {
    $newCover = $uploaded;
    $form['cover'] = $uploaded;
}
```

事务成功后：

```php
if ($newCover !== null && !empty($guide['cover']) && $guide['cover'] !== $newCover) {
    delete_upload($guide['cover']);
}
```

`public/trip_edit.php` 同样，目录 `covers/trips`。数据库异常时删除刚上传的文件。

#### 用户头像

`public/profile.php`，字段 `avatar_file`，目录 `avatars`。

#### 资源封面

- 只支持单张封面，不支持正文内嵌图片/图库；
- 旧图删除只在“同目录替换”时发生，外链图片不会被删除；
- 生产环境还应加病毒扫描、图片压缩、对象存储和更严格的目录权限。

## 8. 安全设计

### 8.1 SQL 注入

- 所有 SQL 都用 PDO 预处理，参数通过 `?` 绑定；
- 不把用户输入拼进 SQL；
- 动态排序只接受白名单值（`new/hot/collect/comment`），不直接拼 `ORDER BY` 用户字符串。

### 8.2 XSS

- 所有用户数据输出都经过 `e()`；
- 富文本正文也只输出纯文本（`nl2br(e(...))`），不执行 HTML；
- 上传只允许图片 MIME，不允许 SVG/HTML。

### 8.3 CSRF

- 所有 POST 表单带 `csrf_field()`；
- 处理 POST 前 `verify_csrf()`；
- 登录成功重置 Token。

### 8.4 越权

- 页面级：`require_login()`、`require_admin()`；
- 数据级：`can_edit_guide()`、`can_edit_trip()`、`can_manage_team()`、`can_edit_route()`；
- 列表查询把可见性写进 SQL，而不是只靠页面隐藏按钮；
- 详情页对私有数据返回 404，不泄露“存在但无权”。

### 8.5 文件上传

- 5MB 限制；
- MIME 白名单；
- `getimagesize()` 二次验证；
- 随机文件名，避免覆盖和路径猜测；
- `delete_upload()` 限制目录；
- 上传目录只放静态资源，不允许执行 PHP。

### 8.6 其他

- Session Cookie `httponly`、`samesite=Lax`；
- 密码 `password_hash/password_verify`；
- 登录后 `session_regenerate_id(true)`；
- 管理后台不能禁用自己/最后一个管理员；
- 生产环境应再加登录限流、审计日志、HTTPS、CSP。

## 10. 开发过程中遇到的主要问题

### 10.1 MySQL CHECK 与级联外键冲突

报错：

```text
ERROR 3823 (HY000): Column 'user_id' cannot be used in a check constraint
'chk_friendship_not_self': needed in a foreign key constraint
'fk_friendship_user' referential action.
```

原因：`CHECK` 列同时带 `ON DELETE CASCADE`。

解决：相关外键改 `RESTRICT`，应用层软删除。

### 10.2 队伍可见性导致申请流程走不通

现象：bob 在队伍列表看不到 `visibility='team'` 的招募队伍；即使进入 `team.php`，待审核申请人也看不到页面。

解决：

- `teams.php` 增加“登录用户 + 队伍可见 + recruiting”条件；
- `team.php` 允许登录用户查看招募中的队伍；
- 待审核申请人可查看队伍页。

### 10.3 资源缩略图把 PDF/MP4 塞进 `<img>`

现象：资源列表出现破图。

解决：新增 `resource_thumb()`；有封面用封面，照片用 file_url，视频/文档无封面返回空串，页面显示类型图标。

### 10.4 行程头图白字压图

现象：封面图本身的亮色区域让白色标题看不清。

解决：`.trip-hero` 固定最小高度 + `background-size:cover`；`.trip-hero-overlay` 加底部深色渐变。

### 10.5 私聊发送按钮竖排

现象：textarea 和按钮在同一行时，按钮被挤成很窄的一列，“发送”两个字竖着显示。

解决：textarea 加 `flex-grow-1`，按钮加 `flex-shrink-0`。

### 10.6 Playwright 登录点错按钮

现象：脚本用 `button[type="submit"]`，点到页头的搜索按钮，登录没成功，后续页面 404。

解决：改用 `form:has(#login) button[type="submit"]`，并断言登录后导航出现“通知/私聊”。

### 10.7 沙箱下浏览器/命名管道被拒绝

现象：Chrome headless 报 `mojo ... platform_channel.cc ... 拒绝访问`、crashpad `OpenProcess: 拒绝访问`。

解决：截图/浏览器测试用完全权限运行；npm 缓存放到工作区 `tools/.npm-cache`，避免写用户目录被拒绝。

## 12. 已知限制与可扩展方向

### 12.1 已知限制

- PHP 内置服务器不适合生产并发；
- 管理后台是精简版：没有改角色、重置密码、删除用户、评论管理、举报处理、操作日志、批量操作、后台分页；
- 没有 WebSocket/轮询，私聊和通知需要刷新页面；
- 没有邮件/短信验证、找回密码；
- 上传只支持单张图片，没有压缩、裁剪、图库；
- 没有完整 RBAC，只有 user/admin 两种角色；
- 路线编辑校验失败时，如果所有行都为空，可能需要重新填写；
- 后台审核 POST 后 redirect 使用 `query('status')` 读 GET，某些情况下会丢筛选（不影响数据）。

### 12.2 可扩展方向

- 引入 Composer + 轻量框架/路由；
- 用对象存储替换本地 uploads；
- 增加图片压缩、缩略图；
- 私聊改为 WebSocket；
- 管理后台增加审计日志、举报、评论管理；
- 增加行程地图、天气、预算分摊；
- 增加单元测试/PHPUnit；
- 部署到 Nginx + PHP-FPM + HTTPS。

## 14. 小结

这个项目的实现重点可以概括为四句话：

1. **页面是入口**：每个 `public/*.php` 自己处理 GET/POST，加载公共 bootstrap，查库、校验、渲染；
2. **公共逻辑下沉**：配置、PDO、认证、CSRF、转义、上传都在 `app/`，页面不重复造轮子；
3. **数据库承担约束与业务**：外键、CHECK、唯一键、视图、存储过程、触发器、事务、行锁都在 SQL 里，而不是只靠 PHP 判断；
4. **上传统一走文件选择**：`save_image_upload()` 负责校验和落盘，数据库只保存 `/uploads/...`，`delete_upload()` 负责安全清理旧图。

如果需要继续扩展，建议优先补：后台审计/举报、私聊实时化、图片压缩、路线地图、自动化测试。
